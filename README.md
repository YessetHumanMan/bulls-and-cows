# Bulls and Cows

Браузерная игра на TypeScript с функциональным ядром и разработкой через TDD.
Бэкенда и внешних API нет. Рекорды сохраняются локально в браузере.

## Запуск

Проверено на Node.js 24 и npm 11.

```bash
npm ci
npm run dev
```

Откройте адрес, который Vite выведет в терминале (обычно `http://localhost:5173`).

## Как играть

1. Выберите систему счисления: bin, oct, dec или hex.
2. Выберите длину от 2 до 6. Для bin доступна только длина 2.
3. Нажмите **Start game** — настройки заблокируются до новой игры.
4. Введите уникальные цифры и нажмите **Check guess** или Enter.
5. Bull — правильная цифра на своём месте, cow — правильная цифра на другом месте.
6. Угадайте все цифры, чтобы увидеть число попыток и время.
7. **New game** возвращает к настройкам без перезагрузки, в том числе во время раунда.

Секрет может начинаться с нуля. Для hex регистр не важен. Повторная попытка не
добавляет запись в историю. Лимита попыток нет.

## Рекорды

Общий топ-10 сортируется по числу попыток, при равенстве — по времени.
Для каждой записи показаны длина и основание системы счисления.
Рекорды переживают обновление страницы и сохраняются между раундами.

Данные хранятся в `localStorage` под ключом `bulls-and-cows-records` и привязаны
к origin сайта. Очистка данных браузера удалит рекорды. При недоступности хранилища
результаты остаются в памяти до перезагрузки, приложение показывает предупреждение.

## Команды

| Команда                | Назначение                                         |
| ---------------------- | -------------------------------------------------- |
| `npm run dev`          | Локальный сервер разработки.                       |
| `npm run build`        | Проверка TypeScript и production-сборка в `dist/`. |
| `npm run preview`      | Локальный просмотр собранного приложения.          |
| `npm run lint`         | Проверка ESLint.                                   |
| `npm run format`       | Форматирование Prettier.                           |
| `npm run format:check` | Проверка форматирования без изменения файлов.      |
| `npm run typecheck`    | Проверка типов без сборки.                         |
| `npm test`             | Однократный запуск Vitest.                         |
| `npm run test:watch`   | Тесты в watch-режиме.                              |

`npm test` допускает пустой набор тестов для начального setup-коммита.
Теперь в проекте 138 тестов ядра и хранилища.

### Git hooks

- `pre-commit`: только `lint-staged`, ESLint и Prettier для изменённых файлов.
- `pre-push`: `npm test`, блокирует отправку с падающими тестами.
- Husky настраивается через `prepare` при установке зависимостей.

Красный и зелёный коммиты остаются отдельными; push выполняется после реализации,
когда вершина ветки уже проходит тесты. Не объединяйте TDD-пары через squash.

## Структура

```text
src/
  core/       # Генерация, сравнение, валидация, состояние, сортировка
  types/      # Readonly-типы настроек, состояния, попыток и рекордов
  storage/    # localStorage и проверка сохранённых данных
  ui/         # Настройки, ввод, история и таблица рекордов
  main.ts     # Связывание экранов и внешних зависимостей
  styles.css  # Адаптивное оформление
tests/        # Vitest: ядро и storage
```

`body` в HTML содержит только script. Вся разметка создаётся TypeScript-кодом,
без `innerHTML` и `insertAdjacentHTML`. Игровая логика не зависит от DOM и не использует классы.

Подробнее: [DESIGN.md](DESIGN.md) — структуры данных, алгоритмы, Big O и Clean Code.

## TDD

Для каждой обязательной функции сначала создан коммит с падающими тестами,
затем отдельный коммит с реализацией:

| Функция                | Красный коммит | Зелёный коммит |
| ---------------------- | -------------- | -------------- |
| `createDigitValidator` | `90534c0`      | `e8d2e4b`      |
| `isValidGuess`         | `677be4e`      | `b70a582`      |
| `generateSecret`       | `4020a95`      | `c56d118`      |
| `evaluateGuess`        | `a40c706`      | `75fd515`      |
| `countPossibleSecrets` | `d50c9ed`      | `4d3d0f3`      |

Дополнительно через красный/зелёный коммиты реализованы иммутабельное состояние
(`3d22ca3` → `8cf02c2`) и сортировка рекордов (`f8d4683` → `cda645b`).

Историю можно посмотреть командой:

```bash
git log --reverse --oneline main..bulls-and-cows
```

Например, для проверки обязательной TDD-пары в отдельном рабочем каталоге:

```bash
git worktree add --detach ../bulls-and-cows-red 90534c0
cd ../bulls-and-cows-red
npm ci
npm test # Ожидаемо падает на заглушке createDigitValidator.
git switch --detach e8d2e4b
npm test # Ожидаемо проходит.
```

## Проверка текущей версии

```bash
npm run lint
npm run format:check
npm run typecheck
npm test
npm run build
```

В локальной production-сборке проверены настройки, ограничения bin, фильтрация
ввода, uppercase hex, повторы, история, победа, время, новая игра и сохранение
рекордов после reload. Адаптивность проверена на 320, 768 и 1920 px.

## Деплой и сдача

**Игра:** https://yessethumanman-bulls-and-cows.netlify.app

Сайт опубликован на Netlify, исходный GitHub-репозиторий остаётся приватным.
[`netlify.toml`](netlify.toml) задаёт Node.js 24, сборку `npm run build` и публикацию `dist/`.
Бэкенд и серверные функции не используются.

Для обновления сайта из рабочей ветки:

```bash
npx netlify-cli login
npx netlify-cli link --id a0fb3053-ff23-42cd-b2e4-89c6659e1510
npm test
npx netlify-cli deploy --prod
```

Последняя команда запускает сборку и публикует результат. Для публикации нужны права
в Netlify-команде владельца. Автодеплой из GitHub пока не подключён: публикация выполняется
через CLI. Локальная привязка `.netlify/` исключена из Git.

Рабочая ветка — `bulls-and-cows`. В `main` остаются только начальные README и `.gitignore`.
Итоговый PR открывается из `bulls-and-cows` в `main`, без merge.
