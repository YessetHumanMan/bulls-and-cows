# Архитектура Bulls and Cows

## 1. Структуры данных и границы приложения

### Настройки и состояние

Типы определены в [`src/types/game.ts`](src/types/game.ts):

- `GameSettings` хранит длину и основание системы счисления.
- `GameState` хранит настройки, секрет, статус, историю и время начала/завершения.
- `Attempt` содержит нормализованную попытку и результат `{ bulls, cows }`.
- Секрет и попытки представлены строками: ведущий ноль в `0123` не теряется.
- История — `readonly Attempt[]`: порядок попыток важен, а добавление в конец удобно
  выражается через новый массив.

`readonly` защищает от случайных изменений на уровне TypeScript, но не замораживает
объекты во время выполнения. В тестах состояния дополнительно используется
`Object.freeze`, чтобы обнаружить мутации.

В [`createGame`](src/core/game-state.ts) настройки копируются, история создаётся заново.
[`submitGuess`](src/core/game-state.ts) не меняет переданное состояние: новая попытка
добавляется через `[...state.history, entry]`, а состояние — через `{ ...state, ...changes }`.
Старые записи остаются на месте. Невалидная, повторная или отправленная после победы
попытка возвращает прежнее состояние.

### Чистое ядро и побочные эффекты

[`src/core`](src/core) не обращается к DOM, часам или `localStorage` и не содержит классов.
Время передаётся числами в `createGame` и `submitGuess`.

Границы с внешним миром:

- [`src/main.ts`](src/main.ts) связывает экраны, получает время и создаёт ID рекорда;
- [`src/ui`](src/ui) создаёт DOM и обрабатывает действия пользователя;
- [`src/storage/records-storage.ts`](src/storage/records-storage.ts) читает и записывает JSON.

У `generateSecret` источник случайности передаётся параметром. По умолчанию это
`Math.random`, поэтому обычные вызовы не являются детерминированными. Тесты передают
свой предсказуемый `random`. Это позволяет проверять генерацию без настоящей случайности.

### Рекорды

[`GameRecord`](src/types/record.ts) содержит ID, длину, основание, число попыток,
длительность в миллисекундах и дату завершения.

Используется общий топ-10: длина и основание явно показаны в каждой строке таблицы.
[`sortRecords`](src/core/records.ts) сортирует копию массива сначала по попыткам,
затем по времени и возвращает первые N записей. Исходный массив не изменяется.

Хранилище использует ключ `bulls-and-cows-records`. При чтении проверяются структура
и значения записей. Повреждённый JSON не ломает приложение, невалидные записи
отбрасываются. Если запись недоступна, рекорд остаётся в памяти текущей страницы,
а пользователь видит предупреждение.

## 2. Алгоритмы и функциональные приёмы

### `generateSecret(length, base, random)`

Файл: [`src/core/generate-secret.ts`](src/core/generate-secret.ts).

1. Проверяем целые значения параметров и условие `1 <= length <= base <= 16` при `base >= 2`.
2. Создаём локальный массив из первых `base` символов `0123456789abcdef`.
3. Перемешиваем его алгоритмом Fisher–Yates, используя переданный `random`.
4. Берём первые `length` символов и соединяем в строку.

Цифры изначально уникальны, поэтому повторов не возникает. Ноль не исключается
из первой позиции. Ожидается источник случайности с результатом в диапазоне `[0, 1)`.
Изменяется только новый локальный массив, а не входные данные или состояние игры.

### `evaluateGuess(secret, guess)`

Файл: [`src/core/evaluate-guess.ts`](src/core/evaluate-guess.ts).

Обе строки приводятся к нижнему регистру. Из секрета создаётся `Set` для проверки
наличия цифры. Первый `filter` считает совпадения цифры и позиции — bulls.
Второй `filter` считает цифры, присутствующие в секрете, но стоящие в другой позиции — cows.
Bulls повторно в cows не учитываются.

Предусловие: секрет и попытка одинаковой длины и состоят из уникальных цифр.
В игровом процессе попытка проходит `isValidGuess` до сравнения.

### `createDigitValidator(base)` и `isValidGuess(guess, length, base)`

Файлы: [`digit-validator.ts`](src/core/digit-validator.ts),
[`validate-guess.ts`](src/core/validate-guess.ts).

Фабрика фиксирует алфавит системы в замыкании и возвращает предикат `(char) => boolean`.
Это каррированная по смыслу проверка: сначала задаётся основание, затем символ.
Принимается ровно один символ, регистр hex не важен.

Предикат используется в двух местах:

- `isValidGuess`: `every(isValidDigit)` проверяет допустимость цифр;
- [`createGameView`](src/ui/game-view.ts): `beforeinput` блокирует недопустимый ввод,
  а обработчик `input` фильтрует вставку и другие изменения поля.

`isValidGuess` также проверяет длину и уникальность через `Set` после `toLowerCase`.
Поэтому `a` и `A` считаются одной цифрой. `filter`, `every`, `some` и callbacks
используются для решения задач ядра, а не только для отрисовки.

### `countPossibleSecrets(length, base)`

Файл: [`src/core/count-possible-secrets.ts`](src/core/count-possible-secrets.ts).

Считаем перестановки без повторений. Используется эквивалентная рекурсивная формула:

```text
P(base, 0) = 1
P(base, length) = (base - length + 1) * P(base, length - 1)
```

Например, `P(10, 4) = 7 * 8 * 9 * 10 = 5040`. Секреты с ведущим нулём включены.

`Map<string, number>` хранит результаты по ключу `length:base`, включая промежуточные
рекурсивные вызовы. Повторный запрос возвращается из кеша. Кеш внутренний:
он изменяется, но не доступен вызывающему коду и не влияет на значение результата.
Отрицательные, нецелые и невозможные параметры отклоняются через `RangeError`.

## 3. Сложность

Обозначения: `n` — длина строки, `b` — размер алфавита, `l` — длина секрета.
Оценки приведены по размеру входа, хотя интерфейс ограничивает длину значениями 2–6,
а размер алфавита — 16 символами. Для `Set` и `Map` предполагается средняя O(1) операция.

| Функция                                    | Время                             | Дополнительная память | Обоснование                                                                                                                                  |
| ------------------------------------------ | --------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateSecret`                           | O(b)                              | O(b)                  | Создание и перемешивание b цифр; получение результата O(l), где l <= b.                                                                      |
| `evaluateGuess`                            | O(n)                              | O(n)                  | Создание массивов и Set, затем два линейных прохода через `filter`.                                                                          |
| `isValidGuess`                             | O(n) для поддерживаемых оснований | O(n)                  | Нормализация, `every` и создание Set. `includes` просматривает максимум 16 символов. Если считать b неограниченным, общая оценка — O(n * b). |
| `countPossibleSecrets`, первый вызов       | O(l)                              | O(l)                  | На каждом уровне длина уменьшается на 1; стек и новые записи кеша растут линейно.                                                            |
| `countPossibleSecrets`, кешированный вызов | O(1)                              | O(1) дополнительной   | Проверка параметров и чтение уже сохранённого результата. Существующий кеш при этом остаётся в памяти.                                       |

Кеш сохраняется на время работы страницы. O(l) памяти в таблице — оценка одного
холодного вызова, а не всего кеша после запросов для разных оснований.

## 4. Принципы чистого кода

| Принцип                           | Где применён                                                                                                            |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Одна ответственность              | `evaluateGuess` только сравнивает, `isValidGuess` только проверяет, storage-модуль только читает/записывает записи.     |
| Понятные имена                    | `startedAt`, `finishedAt`, `durationMs`, `createDigitValidator`, `submitGuess` описывают назначение и единицы времени.  |
| Отсутствие дублирования           | `createDigitValidator` используется и в ядре, и в UI; `sortRecords` — при сохранении и загрузке рекордов.               |
| Ранние возвраты                   | `submitGuess` сразу отклоняет невалидные и повторные попытки; `createRecordsView` отдельно обрабатывает пустую таблицу. |
| Явные зависимости                 | `generateSecret` получает `random`, функции состояния — время, UI — callbacks `onStart`, `onWin`, `onNewGame`.          |
| Неизменяемые входные данные       | `submitGuess` создаёт новые state/history, `sortRecords` сортирует `[...records]`. Типы используют `readonly`.          |
| Разделение логики и представления | В `src/core` нет DOM; разметка создаётся в `src/ui` через `createElement`, `textContent`, `append`.                     |
| Именованные константы             | `STORAGE_KEY` в storage-модуле хранит ключ отдельно от операций чтения/записи.                                          |

## 5. Тестирование и TDD

Vitest запускает тесты ядра и storage без браузера. Тесты не используют сеть,
реальный таймер или настоящий `localStorage`: время передаётся параметрами,
случайность детерминирована, хранилище подменяется и очищается после теста.
Это делает тесты быстрыми, независимыми, повторяемыми и самопроверяющимися (FIRST).

Для пяти обязательных функций красный коммит содержит тесты и заглушку,
выбрасывающую `Not implemented`. Следующий коммит заменяет заглушку реализацией.
Таблица этих пар находится в [README](README.md#tdd).

`pre-commit` запускает только `lint-staged`, поэтому не мешает красному коммиту.
`pre-push` запускает `npm test`: отправлять нужно уже зелёную вершину ветки,
сохраняя оба коммита в истории.
